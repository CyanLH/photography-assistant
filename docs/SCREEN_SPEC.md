# 화면 및 인터랙션 명세

## 디자인 원칙
날씨 수치가 아니라 ‘다음 촬영 행동’을 우선한다. 모바일 현장 도구의 실용성과 아날로그 사진 장비의 차분한 느낌을 결합한다. 기본 색은 아이보리/녹회색, 계기판은 짙은 녹색, 태양은 골드, 달은 청보라, 프레임 방향은 연녹색. 주 색상은 design-tokens.json에 있다.

타이포그래피는 시스템 한국어 고딕을 사용한다. 서비스명 텍스트를 제외한 읽는 문장은 좁게 조이지 않는다. 프로덕션 본문은 16px 이상을 우선하고 단위·시각·보조 상태만 작게 사용한다. 프로토타입은 밀도를 비교하기 위한 작은 보조 텍스트를 포함한다. 실제 야외 테스트에서 가독성 기준으로 조정한다.

## S02 레이아웃
데스크톱: 90px 아이콘 내비게이션 레일, 53px 상단 바, 압축된 제목+위치/촬영 의도 탭, 거의 전폭 2열 콘텐츠(큰 나침반 / 추천·날씨·노출), 전폭 시간 슬라이더.
모바일: 51px 헤더, 압축된 제목·위치, 4개 의도, 더 큰 작업 영역의 나침반과 방위, 첫 화면에서 시작이 보이는 추천 카드, 날씨, 시작 설정, 시간 이동, 하단 4개 내비게이션. 프로덕션에서는 방향 맞추기 행동을 첫 화면에서 접근 가능하게 유지한다.

태양/달 표시는 방위선과 고도 값을 분리한다. 원형 나침반의 반경으로 고도를 나타내지 않는다. 프로토타입의 태양/달 마커 반경은 서로 구분하기 위한 시각 배치다. 북쪽 고정 상태와 실제 카메라 방향을 모른다는 사실을 유지한다.

추천 화각은 ‘장비로 보이는 범위’이고 ‘좋은 사진을 보장하는 범위’가 아니다. 초점거리가 길어질수록 화각 부채꼴이 좁아진다. 태양 방향과 추천 촬영 방위는 의도에 따라 다를 수 있다.

## S04 Google 지도 레이아웃과 제공자 계약
- 지도 제공자: **Google Maps JavaScript API 단일 공급자**. 기획된 프로덕션 Next.js 환경변수 `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` 및 `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID`를 사용. 프로젝트 `.env.example`은 이름만 기재.
- 데스크톱 지도는 컨텐츠 폭의 대다수를 차지하고, 보조 컨트롤 영역은 약 292px. 지도 높이는 대략 `100dvh - 154px` 이상(최소 660px).
- 모바일 지도는 타이틀과 하단 내비게이션을 제외한 가용 높이만큼 확대(`100dvh - 157px`, 최소 500px). 설명 패널은 세로 스크롤 아래로 보낸다.
- A(촬영자)와 B(피사체)는 실제 `lat/lng`로 저장하고 지도 클릭/핀 드래그로 이동. 방향각은 A→B의 진북 시계방향 bearing, 반경 220m의 부채꼴은 실제 렌즈 수평 화각의 예시 투영이다. 태양·달 방위선은 선택 좌표·시각 기반 계산값이며 실제 지형 차폐·기상 관측값이 아니다.
- Google 로고·저작권/상호작용 컨트롤이 UI 요소로 가려지지 않게 배치한다. API 키가 없거나 실패하면 도식 대체 화면으로 명시하고 실제 지도로 위장하지 않는다.
- 프로토타입 시작 좌표는 예시 서울 근방이다. 사용자가 위치 사용을 선택하면 Geolocation API로 현재 좌표를 받고 천문을 즉시 재계산한다. 날씨는 계속 예시이며 Google Maps API 키는 별도로 필요하다.

## 상태 공유
- 시각, 의도, 장비는 화면 간 유지한다.
- 지도에서 설정한 피사체 핀의 방위는 ‘사용자 구도’다. 엔진 추천 방위와 다른 값일 수 있다. `추천 방향으로 초기화`를 명시적으로 누른 경우에만 추천에 맞춘다.
- 장비 변경은 화각과 시작 설정을 즉시 갱신하되 브라우저 영구 저장은 별도 저장 버튼으로 실행한다.
- 저장 계획에는 장비 snapshot, 시각, 촬영 의도를 보존하고 불러올 때 함께 복원한다.
- 계획 목록은 최신 5개만 보관하는 프로토타입 제한이다. 제품 제한은 별도로 결정한다.

## 프로토타입에서 동작하는 것
네 화면 전환, Google Maps 키 입력 시 지도 타일·A/B 지리 핀·방향선·화각 polygon(키가 없으면 명시적 도식), 노을/풍경/인물/달 추천, 시간 이동에 따른 실제 계산 태양·달 이동 및 달 위상 SVG, 맑음/흐림 예시, 조건부 추천 변경, 렌즈/센서/프레임 방향별 화각 계산, 최대 개방 반영, 삼각대 상태, 개념 지도 핀 이동, 수동 참고 방위, 모달, 로컬 장비·계획 저장/불러오기/삭제.

## 실제 제품에서 추가할 것
나침반 권한, 실제 기상 API, 장소별 IANA 시간대, 고정밀 천문 엔진 검증, Google Maps 실 키·결제·Referrer 제한 실검증, Google 지도 접근성/주소 입력, 날짜·시간대 선택, 바람/위험 조건 규칙, 고위도/DST 예외, 통합 테스트, PWA, 성능/접근성 감사. 프로토타입에 없는 P0 기능은 PRD와 구현 로그에서 추적한다.

## 실패 화면 문구
위치 거부: ‘현재 위치 대신 지도에서 촬영 장소를 정할 수 있어요.’
나침반 거부: ‘자동 방향을 사용할 수 없어 북쪽 고정 지도로 안내해요.’
날씨 실패: ‘날씨를 가져오지 못했어요. 태양과 달의 계산 정보만 보여드려요.’
오래된 데이터: ‘마지막으로 받은 예보예요. 현재 날씨와 다를 수 있어요.’
달 수평선 아래: ‘선택한 시각에는 달이 수평선 아래에 있어요.’
차폐 미확인: ‘이 방향의 건물·나무·산은 확인하지 못했어요.’

## 키보드·모션·폰트
프로덕션은 모든 기능을 키보드로 사용할 수 있게 한다. 지도 클릭의 대체 입력 필드를 제공한다. 모달은 focus trap/ESC/복귀를 지원한다. 색상만으로 상태를 구분하지 않는다. 설정이 제한된 시스템/파일 URL에서도 storage 실패로 crash하지 않는다. 사용자 기기에 설치된 폰트만 사용하며 폰트 파일은 이 패키지에 포함하지 않는다.

## 디자인 검증 크기
360×800, 390×844, 768×1024, 1440×1080. 화면 높이가 작은 기기는 정상적인 세로 스크롤을 허용한다. 하단 내비게이션과 고정 행동이 콘텐츠를 가리지 않도록 padding과 safe area를 계산한다.

## v3 간결한 페이지 제목

- 현장 가이드 / 빛 지도 / 시간 계획 / 내 장비. 장식적인 서브카피, 감성적인 슬로건, 브랜드 로고는 사용하지 않는다.
- 현장 화면에는 달 원반 위상 그림, 위상 이름, 밝은 비율, 고도 및 방위와 함께 선택 좌표의 태양 위치를 제공한다.
- 시간 계획에는 골든·블루아워의 네 구간, 일출·일몰, 24시간 고도 차트를 보여준다. 값이 없다면 명시적으로 해당 날짜에 없음이라고 한다.
